The teaching model

Teach it, practise it, then assess it.

Each unit of competency runs through the same rhythm. The skill is taught in class, rehearsed on a live engagement, and only then assessed for real.

The no-leakage rule. A student meets a system as a worked example in one cluster, then is assessed on a different system in another — so the assessment vehicle is never one they've already been walked through. Integrity is built into the structure, not policed after the fact.

The craft of it

Practice mirrors the assessment — without handing over the answer.

A practice task is the assessment decomposed step-for-step, then re-set on another system with a deliberately different profile. The skill transfers; the solution can't.

Assess The LMS

  • Public-facing, student-critical
  • 99.9% availability target
  • MySQL, open-source stack
  • Global, anonymous audience

Practice Ledgerline

  • Internal, business-hours only
  • 99.5% target — a different bar
  • SQL Server, commercial licensing
  • Staff over a campus VPN

Because the profiles genuinely differ, a student who reasons well on Ledgerline still has to reason — not copy — on the LMS. The practice proves the method; the assessment proves the person.

Where the scenario lives

The intranet is the single source of truth.

Everything — role briefs, client requirements, system records, policies — is published on one YAT intranet. Students don't get a handout; they consult the site the way a real consultant consults a client's documentation.

  • ✦In-world only. No course or assessment language leaks onto the site — it reads as YAT's real operations.
  • ✦State-versioned. Each system has a history. A task set “post-cutover” shows the student the system exactly as it stood then — not before, not after.
  • ✦Single-sourced. Every cluster references the same world, so the story stays consistent across a full year of assessment.

Cluster 1 · in depth

Cloud Design & Build

YAT's learning platform is stuck on ageing on-premise servers and the India launch needs it to scale. MTS is engaged to move it to the cloud — and the cluster follows that job through three acts.

I

Make the case

Should YAT move the LMS to the cloud — and why?

II

Build the foundation

Stand up the cloud environment it will run on.

III

Make it resilient

Harden the live system so an outage can't take it down.

Cluster 1 · Act I — Assessment 1

The Business Case.

MTS reviews the ageing on-prem LMS and builds the case to move it to AWS — costs, benefits, risks and options weighed against YAT's growth. Then the student presents it to YAT's board and defends the recommendation live.

It's the analyst-and-advisor skill: turn a technical decision into a business argument a non-technical board will approve.

UnitICTICT517
DeliverableBusiness case + board presentation
Assessed onThe LMS
Practised onLedgerline

Cluster 1 · Act II — Assessment 2

The Cloud Foundation Build.

With the migration approved, MTS builds the cloud environment from a supplied design — network, compute, database and storage — and hands back a Deployment Report evidencing what was stood up and tested.

MTS owns the cloud infrastructure only — YAT's own IT deploys the application and migrates the data. A clean, real-world scope line the students learn to respect.

UnitICTCLD401
DeliverableDeployment Report + appendices
Built fromA supplied baseline design
LabAWS Academy

Cluster 1 · Act III — Assessment 3

High Availability.

The LMS is now live. In a simulated Saturday-night maintenance window, MTS hardens it in place — spreading the app tier across Availability Zones and converting the database to Multi-AZ with automatic failover — then proves it with a live failover demonstration.

Design it, deploy it, and show it survives a zone failure — without a re-build and without touching the data.

UnitICTCLD502
DeliverableHA design + HA deployment report
ProofLive Multi-AZ failover
FramingPost-cutover, in-place

Cluster 1 · how they rehearse

They practise on Ledgerline, then sit the LMS.

Every LMS assessment has a twin on Ledgerline, YAT's accounting system — same three acts, a different client profile. Students see it on the intranet as just another live MTS engagement, indistinguishable until the task is handed out.

Act I → practice

Build the accounting migration business case — an internal, cost-sensitive system, not a public one.

Act II → practice

Deploy the Ledgerline baseline — SQL Server, an internal load balancer over the campus VPN.

Act III → practice

Design its high-availability hardening to a 99.5% bar — a different target, a different judgement call.

By the time a student opens the LMS assessment, they've run the whole arc once — on a system whose answers won't fit.

The shape of the year

Three clusters, one escalating story.

  • 1Cloud Design & Build — move the LMS to the cloud and make it resilient. The foundations: business case, build, high availability.
  • 2Cloud Disaster Recovery — scale the website for a global audience and design it to survive a region loss. The step up: design and implement at web scale.
  • 3Infrastructure Improvement — a student leads a team to improve Ledgerline. The capstone: technical improvement plus real team leadership.

Difficulty, autonomy and scope all climb — from advising on one system, to building at scale, to leading a team. The India-expansion thread ties all three to one client's real year.
